# 管理员面板与手机号账号

依据：用户于 2026-10-05 明确要求创建管理员面板、提供管理员账号，并配置两位手机号和指定密码。沿用已授权的 Codex/子代理开发与上海 ECS 发布流程；真实凭据只用于受保护的初始化输入，不进入源码、测试或文档。

## 设计

- 成员通过手机号和密码登录，旧邮箱账号继续兼容。手机号唯一；密码继续使用 Argon2id。
- 保留现有首位成员、空间与全部内容，为现有成员绑定手机号，第二位成员进入原空间的第二个位置。业务数据不会转移到另一个空间。
- 独立管理员使用单独账号，不占双人空间名额。管理界面 `/admin` 与成员界面分开；管理员不凭角色读取私人照片、点滴或事件流。
- 管理界面显示账号、启用状态、空间与成员位置，允许创建成员、为未配对成员绑定空位置、重置成员密码和停用/启用成员。密码与确认操作在弹窗中完成。
- 不提供删除空间内容、强制换人、公开注册、网页提升管理员权限或执行服务器命令。
- 所有管理 API 验证当前管理员角色；写入检查同源和 JSON，限制频率。重置/停用撤销该成员所有会话；被停用账号不能登录或继续读取内容。
- 新增迁移保留旧账号 ID、邮箱、密码摘要、成员关系和业务内容，旧首位账号不会因名字含 admin 自动成为管理员。
- 初始化命令只接收标准输入中的 JSON，事务内检查已有账号和空间冲突。重复执行不创建重复成员，不把已有成员提升为管理员；错误时整体回滚。

## 实施与验证

1. 后端任务：手机号、角色与状态迁移；登录兼容、实时会话校验；管理服务/API 与权限、并发测试。
2. 前端任务：手机号登录、管理员路由守卫；深色管理面板与表单弹窗、窄屏布局、浏览器流程。
3. 根任务：安全初始化命令，保留原空间并配置两位账号；整合与独立审查。
4. 恢复任务：旧数据迁移和真实空目标恢复测试，验证手机号、角色、状态与原密码保留。
5. 通过类型、单元/集成、安全、浏览器及构建验证后，先备份生产，构建新 Linux 镜像，迁移并事务配置账号，保留原卷和 HTTPS 配置。
6. 实测两个手机号登录后同属原空间，管理员管理接口可用、成员管理接口 403、管理员无成员身份时业务接口 403。生成升级后备份并保存站外副本，完成空目标恢复验证。

实际结果记录在 `docs/admin-phone-acceptance.md`，不以计划中的预期代替验证证据。
