# 和牌详情与统一收支验收

当前状态：本地实现、真实联机、Linux 候选检查、上海 ECS 正式发布与主检出拥有路径同步均已通过。整体“持续对齐雀魂体验”目标保持 active。

## 最终行为

三人和四人普通自摸／荣和先逐位显示赢家详情，再只显示一次整手净收支。每位玩家独立翻页，同一账号多个客户端共享游标；只有最终分数确认等待全桌完成。原生引擎仍计算支付，汇总只累加原生各页 delta。结束手牌快照保持逐席隔离，下一手或终局排名在最终屏障前不公开。

详情以原创揭示排程展示役种和牌型点数；分数从1200ms起以30ms间隔滚动33步，2160ms到最终值。非零收支4500ms开放确认，零收支1200ms；之后3000ms自动确认。设备绝对时钟变化不提前开放。断线、忙碌、卸载、已确认取消发送；请求失败后可手动重试。每位赢家的新页回到顶部，同页推送保留滚动。

- 修正后完整63文件552项测试、类型检查与生产构建通过。此前完整运行分别遇到缺少数据库环境、公开宝牌被旧字符串断言误判、随机测试宝牌改变固定支付；这些失败日志保留，没有将其算作通过。

## 实施取舍

按发生顺序保留执行判断：既有自主开发与发布授权用于本轮，无需重复确认（代价：设计不合适时需要本地返工）；支付继续由原生引擎计算，未证实的本场多荣差异保留（代价：不能宣称评分完全一致）；旧隐私断言改查私有字段而不搜整个DTO牌码，公开宝牌是合法公开字段（代价：未来新增私有字段仍需扩展验证）；测试物理墙固定真实宝牌副本，消除随机宝牌改变固定支付的误判（代价：随机覆盖仍靠其他用例）；详情采用每席游标、只有最终分数等全桌，并重置新赢家滚动（代价：客户端时序需继续实机观察）。

打包方面，BuildKit把原始镜像编号误认作远端地址，改为从固定ID创建本地别名并核对父层；原始dockerignore遗漏.next，使用专用排除文件保留冻结构建；20秒前台远程测试被截断，改为有120秒上限的后台任务并检查真实终态（代价均为：校验失败则拒绝发布）。旧build退出记录引用也在新命令里纠正，保留失败证据。没有延后的小型审查发现。
