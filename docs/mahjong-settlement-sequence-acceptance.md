# 和牌详情与统一收支验收

当前状态：本地实现和真实联机验证通过，Linux 候选、正式发布及主检出同步仍待完成。整体“持续对齐雀魂体验”目标保持 active。

## 最终行为

三人和四人普通自摸／荣和先逐位显示赢家详情，再只显示一次整手净收支。每位玩家独立翻页，同一账号多个客户端共享游标；只有最终分数确认等待全桌完成。原生引擎仍计算支付，汇总只累加原生各页 delta。结束手牌快照保持逐席隔离，下一手或终局排名在最终屏障前不公开。

详情以原创揭示排程展示役种和牌型点数；分数从1200ms起以30ms间隔滚动33步，2160ms到最终值。非零收支4500ms开放确认，零收支1200ms；之后3000ms自动确认。设备绝对时钟变化不提前开放。断线、忙碌、卸载、已确认取消发送；请求失败后可手动重试。每位赢家的新页回到顶部，同页推送保留滚动。

## 实际检查

- 原生 RoomStore 物理墙：三／四人双荣、自摸、各席独立游标、最终屏障、旧／重复ACK、返回快照隔离、负分终局，共8项。固定宝牌指示仍保留真实牌数量，四麻136张全量守恒；未改规则算法。
- 新组件16项，既有结算组件／单位11项，真实 HTTP/Socket4项：各席私有手牌、重连、同账号重复连接、越权操作拒绝、三／四人真实电脑ACK与解散。
- 修正后完整63文件552项测试、类型检查与生产构建通过。此前完整运行分别遇到缺少数据库环境、公开宝牌被旧字符串断言误判、随机测试宝牌改变固定支付；这些失败日志保留，没有将其算作通过。
- Chromium与WebKit各覆盖三／四人、667×375和1440×810，共8个场景；真实RoomStore返回值驱动生产GameRoom。两位赢家均使用合法40字姓名，滚动后下一页置顶；三个结果阶段的合法ACK、原生下一手及最终分数、按钮触达和正文／固定确认行不重叠通过。包括一次实际自动确认。浏览器检查不是实际安卓设备验收。
- 独立审查最初发现逐页全桌屏障和跨赢家滚动继承两项Important。实际RED和修复后的GREEN记录在ignored `.local/audit/settlement-sequence-20261008/`；重新审查另行记录。
