# 有归 · 日本三麻与电脑补位

2026-10-06。状态：已按用户批准计划实施并发布 `e4674fc`；Linux、原成员公网、默认十分钟退出及真实备份恢复验收完成，Android 实机验收待设备。

## 使用目标

用户明确选择真正的日本三麻：移除二至八万、支持拔北；三人桌和四人桌都能添加电脑。主要场景是两位成员一起玩，以及一位成员独自练习。复用现有手机号账号、房间码、实时同步和按需子进程；牌局不持久化，生活资料继续持久化。

## 选择与依据

推荐保留 `@kobalab/majiang-core` 的四人引擎与手牌/向听/和牌工具，新增独立三麻驱动和统一的电脑行动接口。当前已安装 1.4.1 的 `Game` 在发牌、轮转、局数、分配和排序处固定为四席，不存在配置一个人数就切换三麻的入口。三麻的三家状态不得用一个隐藏的第四人模拟。

另一种方案是引入 [Riichi Advanced](https://github.com/EpicOrange/riichi_advanced)，它已有三麻规则和多种麻将；但其部署引入 Elixir/Erlang、Rust、Z3 等运行工具，现有登录与界面仍需要适配。此项仅为源码调研，未测量它在本 ECS 的资源占用。第三种方案是只加四人桌电脑席，改动较小，但无法完成用户已确认的三麻范围。

选推荐方案的依据是复用已验收的房间/权限/实时服务，并让三麻差异能独立测试。首版电脑采用本地轻量规则策略，参考 [majiang-ai](https://github.com/kobalab/majiang-ai) 的向听与有效牌思路；不引入神经网络权重或外部模型接口。规则参照 [Riichi Advanced 三麻说明](https://github.com/EpicOrange/riichi_advanced/blob/main/documentation/sanma.md)，下文固定本项目采用的变体，界面提供规则说明。

## 三麻规则

- 只有东、南、西三个席位，使用 108 张牌；移除二至八万，筒/索/字牌照常，每张四枚。赤五筒、赤五索各一枚，没有赤五万。万子宝牌循环为一万与九万互指。
- 每家初始 35000 点；东风战为东一至东三，半庄再包含南一至南三。庄家和了或流局听牌连庄；破产结束，无延长战。最终显示实际点数与名次，首版不加入段位、乌马或筹码。
- 禁止吃；支持碰、明杠、暗杠、加杠、立直、自摸、荣和、振听及流局。沿用已验收的四人计分工具识别役与符翻，三人支付由三麻驱动计算，不能直接采用四家的分配数组。
- 北可保留作为普通字牌，也可在自己的摸牌决策阶段拔出。拔北不破坏门清，每枚拔北加一翻宝牌，不能单独作为和牌役；北为宝牌时，拔出的北另计宝牌加成。拔北需要有合法补牌可取，公开拔北数量后补牌，不翻新的杠宝牌。
- 拔北打断一发及首巡特殊役；立直后只可拔出刚摸到的北，不能修改已有听牌结构。拔北补牌和了不计岭上开花；可抢拔北荣和，但不额外计抢杠役；过掉可胡的北采用当前局临时振听/立直振听规则。普通暗杠仍只允许国士抢杠。
- 自摸采用“自摸损”：非庄家满贯由庄家支付 4000、另一家支付 2000，共 6000；庄家满贯由其余两家各付 4000，共 8000。荣和仍由放铳者支付完整点数。每本场自摸两家各加 100、荣和放铳者加 300；立直棒每次 1000。
- 荒牌未听罚符总额 3000：一人听牌收两家各 1500，两人听牌各收未听者 1500，全听/全未听不交换。双荣和按距放铳者的顺序结算，立直棒归最近的首位和牌者；四人专属的四风/四家立直流局不能直接搬入三麻。
- 保留九种九牌、多人合计四杠流局、流局满贯和役满责任支付的相应三家处理；同一玩家独自四杠继续对局；牌山、补牌、宝牌/里宝牌按服务器规则管理，牌数守恒且不重复发牌。流局后立直棒带入下一局，终局剩余棒归首位。

## 电脑席与界面

创建页增加独立的“三人 / 四人”选择，东风 / 半庄继续保留。大厅空席提供房主专属“添加电脑”，电脑席显示标识并可在开局前移除；提供“电脑补齐空位”。至少需要一位真实普通成员，电脑无需手机号、网站账号或数据库记录。支持两真人加一电脑、单真人加两电脑的三麻，以及四麻所有真人/电脑混合组合。

全部真人准备且席位补齐后，房主开局；电脑自动准备。真人加入前，房主可移除电脑腾位；开局后不换人、不改变规则。重新开一场保留席位类型，真人重新准备。三麻只显示三家桌面、三个结算分配与三个名次，手牌触控和现有暗牌隐私边界保持一致；增加“拔北”合法按钮与公开拔北区。

首版只提供一种“基础陪打”难度。电脑不是随机摸切：优先合法和了，根据向听数、可见剩余有效牌、宝牌与公开危险牌比较切牌；在有役与改善牌效时考虑鸣牌，按合法选项立直/杠/拔北。不承诺专业棋力。电脑仅获得与该席位对应的私有视图、公开牌面和合法选项，不读取其他玩家暗牌或牌山。策略失败时使用当前合法选项回退；胡牌/过/结算确认也必须提交合法选项。

电脑在服务器侧行动，前端无须代打。每次决策有轻微停顿，让真人能看清出牌。同一决策最多执行一次，提交前重新校验房间 ID、版本和决策 ID；多人同时响应继续由规则驱动裁决，不重复胡牌或切牌。策略计算在受限 worker 中执行，设置超时和取消；房间结束或切换阶段后的旧结果丢弃。

## 服务器资源预算

用户随后报告 CPU 峰值与卡死；只读诊断确认发生重启及照片测试容器 OOM，但重启前故障根因尚未确定，详见 `../../server-capacity-2026-10-06.md`。以下为实施时确定的预算约束；人机现已上线，最终实测见 `../../sanma-bots-acceptance.md`。

同一麻将服务最多一个计算 worker，同时只处理一个策略任务；计算目标每次不超过 50ms，200ms 超时即终止对应计算并走合法回退，不做长时间全局搜索。worker 的 JavaScript 堆预算 64 MiB；进程总 RSS、原生内存和启动开销另行测量，不能把堆限额当作总内存上限。所有牌桌共享有界队列，旧决策取消；worker 重启次数受限，连续失败转为轻量回退，避免反复启动耗尽资源。

先对一桌最少真人、最多电脑的完整三麻/四麻进行开发机验收，再在 ECS 以受限任务测量决策延迟、CPU、内存、网站响应及退出后的释放。不在 ECS 同时运行完整测试、构建和图片压力测试。发布前根据网站与麻将共同峰值设置容器资源上限并验证实际生效，为数据库与系统保留余量；策略超时或容器 OOM 不能被忽略并宣称测试通过。

## 生命周期与权限

继续按需启动。电脑行动不视为真人活跃，不能重置真人离线宽限或阻止清桌；全体真人掉线时立即暂停电脑与牌局，真人在十分钟内重连恢复，超时清桌，清空并空闲十分钟后退出子进程。离桌后仅剩电脑时立即释放房间。清桌、解散、父进程退出须取消定时器与 worker，不能留下常驻人机进程。

现有成员身份认证、管理员禁止占席、同源检查、nonce 幂等、roomId/decisionId 校验、限流与跨空间私人资料边界继续适用。添加/移除电脑仅房主可做；请求不能指定电脑的暗牌、策略函数或服务器路径。电脑席的标识不得当作可登录 userId；生产迁移不创建机器人账号。既有四人真人功能保留，并增加三/四人数与席位类型字段的明确校验。

1. 规则夹具验证 108 张牌、禁止二至八万/吃、三席轮转及庄家轮换、拔北补牌/宝牌/立直限制、抢北与振听、自摸损/本场/罚符、双荣和、流局与终局点数守恒。
2. 完整三麻和四麻混合人机局走至结算与最终排名，电脑能合法出牌/鸣牌/立直/胡牌；不以几个随机摸切步骤替代完整对局验证。
3. 验证电脑策略拿不到对手暗牌、worker 超时安全回退、重复/过期动作拒绝、房主权限、席位上限、机器人不创建真实账号，以及全真人离线时电脑立即暂停并最终清桌退出。
4. 独立数据库和浏览器验证两真人加一电脑三麻、单真人加电脑、四人桌补位、拔北实时同步、刷新重连、三家结算、手机无整页溢出。现有四人联机与账号/管理员/生活资料权限回归仍执行。
5. 类型检查、构建、生产依赖检查、Linux 运行和内存快照验证；先备份再发布至已授权 ECS `8.133.186.15`，用原两位成员的临时验收会话验证实际混合对局，随后撤销专用会话，保留原密码、照片和真实空间。备份恢复检查不省略。

本次不包含杭州/四川麻将、真人断线后的自动接管、高级模型难度、战绩/牌谱持久化或开放注册。手机浏览器自动化不能代替真实安卓设备验收。
