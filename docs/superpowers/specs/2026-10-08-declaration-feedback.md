# 立直与和牌声明反馈

## 目标

延续完整雀魂体验目标，补齐立直、荣和、自摸的桌边声明和声音。多荣声明属于一次对局结果，必须在初始声明时完整出现，不能等每位赢家详情翻页后再宣告。采用原创提示声，角色录音素材及真实 Android 验收仍另需完成，不把提示音称为已实现角色语音。

## 数据与行为

SettlementSequenceGame 已完整收集原生结果，新增只含 seat/winMethod 的公开 winDeclarations，按原生赢家次序提供。所有席位获得相同声明列表；每次 view 返回独立拷贝。不得新增其他人的手牌、役种、支付详情或私有 ACK 游标。保留每位观者独立详情页与全桌最终入账屏障。

声明按 room/gameInstance/hand/sequence 身份去重。初始 GET、断线、重连、跳帧与旧结算不能补播。多荣在初始详情页统一声明，后续详情及收支页不重播。立直由真实公开立直弃牌证明，不依赖按钮或低优先级文本反馈。正常和牌桌边声明使用同一结算时钟；途中三家和沿用其既有服务器相对时序。

声音复用 TableAudioPlayer/静音/权限/后台/断线/卸载清理。逐事件等待对应声明真实出现；中断后的声音丢弃。提供原创立直、荣和、自摸短提示，峰值与尾部安全；不引入模型、服务器声音计算或厂商素材。

## 验收

真实原生三/四麻单自摸、多荣、抢杠结果声明；所有席位一致、不可通过修改 view 污染状态、翻页不改变声明、不改变原生点数与最终屏障；draw/流满贯不误作为荣和。声音/动画的首次挂载、GET/断线/重连、多荣初始同时性、自动确认、静音/尺寸变化/卸载以组件及真实浏览器验证。完整 tests/type/build/secrets、一次整阶段独立审查、固定 Linux 候选与受保护 ECS 发布、数据/清理器/禁备份/Public TLS/主目录保护沿用已验证流程。
