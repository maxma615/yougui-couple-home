# 和牌详情与统一收支流程

用户持续目标：完全对齐雀魂的对局体验。当前步骤处理已确认的和牌流程差异，不把本步骤通过视作完整目标完成。允许自主开发、子代理和实际上海 ECS 发布；不重复索取实现许可。

## 依据与当前差异

公开客户端 v0.11.252.w 的 `UI_Win.onConfirm` 依次展示每个赢家，然后仅打开一次 `UI_ScoreChange`。单手 `dadian` 与整手净 delta 分离。分数动画从 1200ms 起以 30ms 间隔更新 33 次，2160ms 完成；非零 delta 在 4500ms 开放确认，全零为 1200ms，随后 3000ms 自动确认。详情确认在该页实际动画结束后开放，之后同样倒数 3000ms。原始来源 `https://game.maj-soul.com/1/v0.11.252.w/code.js`，只读证据见 ignored `.local/audit/settlement-sequence-reference-20261008.md`。

当前引擎每个赢家分别全席 ACK、分别入账；当前 UI 每页都展示一次收支。新流程须为三人与四人普通自摸/荣和提供统一的结果序列。荒牌、途中流局与流满贯具有不同的官方展示路径，将继续按各自证据实施；本步骤保留其现有可用流程，不冒称已经对齐。

## 服务器结果序列

- 新增只依赖 `view(seat)` / `respond(seat, decisionId, choiceId)` 的 `SettlementSequenceGame`；RoomStore 在原生 factory 产物外包装，注入真实引擎/物理墙的测试仍走同一入口。
- 遇到原生和牌结果，保存各席结束时的私有快照与按实际 seat 索引的旧分。严格以原生公开的合法 ACK/decisionId 排空同一手的结果页，收集每页原生 delta；只到原生 handId 变化或终局排名出现为止。循环以席位数为上限，无法推进时抛错，不猜测下一页。
- 内部已经计算好的下一手/排名保持封装；对外显示被冻结的结束快照。先播放 N 个赢家详情，再显示一张汇总分数页。汇总 delta 为各原生 delta 按 seat 求和，newScores 为 oldScores + delta；不从番符或牌型点数反算，不改既有支付/包牌/棒分算法。
- 每席各自持有展示索引、开始时钟和当前 decisionId；同一账号多个客户端共享该索引。点击合法 ACK 立即推进自己的下一赢家或总分页面，不等待其他席翻页。最终总分 ACK 后停在等待状态，直到全席均完成最终总分确认才对外返回原生下一手/排名。重复、过期或伪造操作拒绝。
- `GameView.settlementFlow` 为可选 DTO：`id`、`stage: detail|scores`、`detailIndex`、`detailCount`、`elapsedMs`、`oldScores`、`delta`、`newScores`。elapsedMs 由服务器注入时钟计算；每席的时钟从自己进入该页面起算；客户端使用接收时的相对耗时，不依赖设备绝对时间一致。
- 快照逐席隔离，不把下一手或别人的私有手牌放进返回 DTO；view 的返回值不得修改内存状态。原生引擎的内部结算推进与用户展示 ACK 是不同层，文档不能声称原生内存延迟到最后才记分。

## 界面与时序

- 详情页显示该赢家手牌、鸣牌、里宝、役种、番符与单手点数，以及“第 N / 共 M 位”；不显示整桌收支。
- 使用原创详情揭示动画：入场 300ms，役种每项间隔 180ms（最多按 15 项计算排程），点数揭示 600ms。确认在 `900 + min(15,yaku.length)*180` ms 开放，再倒数 3000ms。它不包含厂商语音时长，不能宣称逐帧一致。
- 分数页仅显示整手收支与三/四席旧分、变化、动画中的分数和最终新分。整数动画33步，起点/终点及确认排程使用上述公开值；转账/名次的厂商完整构图仍需独立视觉验收，不用这个计时通过替代。
- “继续”在揭示期间不可用；开放后可手动提前确认。自动确认只在当前合法 ACK、联网、不忙碌时调用一次。阶段切换、已确认、断线和卸载取消旧计时；重连不能重播已过的动画或发送旧阶段 ACK。减少动态效果时直接展示最终数值，但保留确认阶段与倒数。
- 已有 ranking 时所有牌局结果面板隐藏；最后结果阶段不暴露下一手的牌或提前把房间标记 finished。
- 无 flow 的旧 fixture/流局保持现有面板；实际 RoomStore 普通和牌必须有新 flow，不能仅在演示页面实现。

## 验收与边界

真实物理墙覆盖三麻双荣、四麻单/双荣、自摸、负分终局、棒分；与裸引擎完全走完的结果比较每席总分。确认覆盖重复/陈旧 ACK、逐席视图、刷新、断线/重连、真人与电脑混桌。组件假时钟验证按钮边界、33步、自动确认只发一次与卸载取消；浏览器实际三/四人结果序列验证横屏内容可达和按钮点击，不能用纯 mock 代替真实对局。

本场多荣分配尚无足够官方一手材料：四麻原生只有首赢家本场、三麻当前各赢家200；本步骤不得把其中任一种称作雀魂标准。真实安卓、厂商语音/全部动画、荒牌/流满贯序列与完整终局通知时序继续属于整体未完成项。
