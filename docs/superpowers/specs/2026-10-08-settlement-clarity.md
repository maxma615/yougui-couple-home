# 手机横屏结算与收支展示

用户已授权持续优化麻将体验并直接发布上海 ECS。本次以真实牌局复现的问题为范围，不修改日麻规则、记分时机或牌桌投影。

## 已确认的事实

- Chromium/WebKit 在 844×390 和 667×375 横屏中，当前 sticky 确认栏覆盖和牌手牌与役种；真实命中测试均命中确认栏。滚到底能够看到内容，但初始画面确有遮挡。
- 四麻与三麻在全席确认当前结算后应用该笔收支；多家荣和逐笔结算。`players.score` 为当前已入账值，`settlement.delta` 为当前待确认的单笔变化。
- 雀魂公开客户端的 `UI_ScoreChange` 使用 `old_scores`、`delta_scores` 和 `old+delta` 展示分数变化。牌型点数与包含立直棒、本场的实际收支是不同数据。本次只采用这些可验证的语义，不复制其素材或源码。

## 预期结果

1. 每席明确显示“结算前”、本次“获得/支付/不变”及“结算后”预览。新余额只按该席已入账分数加当前结算的 delta 计算，不修改引擎或先行入账。
2. 三麻双家荣和第一笔确认后，第二笔预览使用第一笔入账后的分数。四麻、三麻、流局、负余额均遵守相同语义。
3. 结算内容采用独立可滚动容器，确认栏在滚动容器之外占据布局高度。内容与按钮不得相互覆盖。手牌、役种及里宝能够滚动到可见区域，按钮始终可操作。
4. 保持真实 Choice、断线/忙碌禁用条件、按座位身份排列、和牌张与闭手/鸣牌的区分。长姓名不挤破网格。
5. 全席确认并进入终局排名后，本局结算不再显示；引擎可能保留最后一笔结算用于历史状态，但已经入账的分数不能再次加上该 delta 预览。

## 验证与边界

真实物理牌墙与实际 Choice 验证四麻自摸、三麻双家荣和的分数预览及 ACK 生命周期；原版本先产生失败证据。真实 North replacement→tsumo 的浏览器场景验证两浏览器、两个横屏尺寸的遮挡、滚动可达性与实际 ack 回调。额外检查桌面及长姓名/公开鸣牌的布局。纯 CSS 不创建镜像实现的单元测试。

这不等同于雀魂全部结算动画、自动确认时序或真实安卓设备验收。发布不生成备份、不下载用户记录或照片；保持已有服务资源限制及清理器不变。
