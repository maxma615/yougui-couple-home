# 麻将桌面共同投影与飞牌

用户持续目标保持完整：标准授权牌面、桌上摆放、出牌及鸣牌反馈、牌山生成与验证机制、真实手机体验。此步骤解决平面俯视与参考透视之间的明显差异，不能作为整个目标完成。

现有授权包含持续开发及 ECS 发布，不再次索要常规实现许可。只改情侣空间，真实用户数据和会话必须保留。

1. 在 GameRoom 引入单个物理桌面 surface，统一投影牌架、河牌、场况台与桌面纹理。头像、宝牌 HUD、底部可触摸手牌与动作保持正常平面；公开副露与拔北仍可查看，声明牌不隐去。
2. CSS 相机先以官方启动指南和发行商实桌画面的远窄近宽、侧边倾斜为观察依据；角度和系数是产品拟合，未获服务器/厂商精确相机参数。实测完整角点与触摸区域后调优。
3. 为飞牌保留端点真实投影四角与 homography，避免原二维角度/统一缩放在倾斜桌上错位。冷打开、静默刷新、重连、取消和 230ms 当前参数继续保持。浏览器不得读取他人的隐藏牌。
4. 先建立旧布局/投影/飞牌四角 RED，再实施；两个子代理分别负责投影捕获和独立真实引擎浏览器。root负责 DOM/CSS、整合、截图检查与完整权限/联机回归。
5. 通过完整布局、动作、单元、类型、构建和独立审查后才发布；在服务器仅 COPY 本机构建，复用受保护发布器与备份核验。不因局部通过标记连续目标完成。

尚未证明：厂商所有动画时序/相机参数，牌山承诺的输入、盐、揭示与 RNG，真实 Android 验收。当前阶段不能以另一日麻软件替代这些证明。

实际兼容性决策：Chromium 使用共同投影；WebKit 在真实截图中即便返回对称 DOM 四角仍绘制左剪切，纯投影矩阵与多种合成设置未修复。以 `@supports (font: -apple-system-body)` 为 WebKit 使用明确的 affine 缩放退路，不能称为与 Chromium 相同透视。WebKit 方位提示放入右上 HUD 空位，通知沿用原平面布局位置。

此阶段自己公开副露与北牌仍在固定底部展示区，保持上轮稳定手牌/副露边界；对手公开牌属于投影 surface。这不是所有物理牌完全共面的最终布局，后续继续核对。
