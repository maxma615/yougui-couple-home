# 日本麻将四人联机 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans task-by-task. User has already approved implementation; proceed within the owned application directory.

**Goal:** 在有归提供按需运行、四人真人日本麻将。

**Architecture:** 使用 majiang-core 同步规则适配器和内存 RoomStore。独立 Node 子进程承载权威牌局、HTTP 指令与 Socket.IO 私人推送；Next 认证后按需唤醒/代理，Caddy 代理同源 socket。没有麻将数据库表或持久化牌谱。

**Tech Stack:** Next/React/TypeScript、@kobalab/majiang-core 1.4.1、Socket.IO 4.8.4；PostgreSQL 仅用于既有会话认证。

**Spec:** ../specs/2026-10-05-riichi.md

## Global Constraints

- 不修改学术端、根包配置或既有用户数据，不提交凭据。
- 四人真人，东风/半庄，25000 点，各门赤五一张，无延长战。
- 牌局仅内存；10 分钟全员离线且无操作清桌；清空并空闲 10 分钟退出。
- 不公开暗牌/牌山，禁止管理员占席与未授权访问。
- 保留原账号、照片持久化与完整备份恢复。

## Review Focus

1. 旧/重复出牌和多家同时响应不能切两张或阻塞下一阶段（任务 1/2）。
2. 推送泄漏他人手牌或重连绕过停用会话（任务 1/3）。
3. 两次同时唤醒生成两局权威状态或空闲停止正在玩的桌（任务 3）。
4. 四人不同情侣空间与第五人猜码（任务 2/4）。
5. 手机转后台再恢复、页面刷新保留本人座位与无整页溢出（任务 4）。
