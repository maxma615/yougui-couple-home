# 情侣小屋 M1 前端实现报告

更新日期：2026-09-23。

## 实现范围

本轮完成 M1 的手机优先前端页面与浏览器交互，不包含 M2 共同日历：

- `/login`：独立账号登录、字段错误、限流/服务错误反馈。
- `/setup`：首位成员建屋、小屋名称、本人名称、恋爱开始日期。
- `/invite/[token]`：最小邀请预览、第二位成员独立账号加入、失效邀请反馈。
- `/home`：北京时间恋爱天数、下一纪念日、有限未完成待办、最近点滴。
- `/settings`：小屋与两位成员名称、恋爱开始日期、邀请链接、修改密码、退出登录。
- `/anniversaries`：列表、新增、详情、编辑、带名称确认删除、年度重复与 2 月 29 日说明。
- `/todos`：未完成/已完成筛选、新增、详情、编辑、完成/恢复、负责人、截止日、带名称确认删除。
- `/moments`：时间线、新增、详情、编辑、带名称确认删除，以及鉴权照片上传、显示和删除。
- 响应式应用壳：手机底部导航和可见同步/退出入口，桌面侧栏；米白、暖粉、深棕的单列卡片视觉。

前端只调用 `docs/implementation-contract.md` 中的真实 REST API，没有生产示例数据或前端 mock 数据。所有 JSON mutation 显式发送 `Content-Type: application/json`，照片使用 `FormData`。

## 并发、刷新与失败处理

- `useHomeUpdates` 订阅 `/api/events` 的 `change` 与 `reset`，事件只作为失效通知并触发重新读取。
- SSE 失败后启用轮询；轮询从固定最小间隔开始，连续刷新失败时逐步退避。恢复在线和页面重新可见时立即刷新。
- 同一时刻只运行一次刷新；期间的新刷新请求合并为随后一次，避免双请求竞态。
- 页面已有会话或资源数据时，后台刷新失败只显示非阻断错误，不卸载页面或编辑器，因此未保存草稿仍保留。
- 编辑返回 409 时同时显示服务器最新内容与我的输入，支持明确载入服务器版本，或使用服务器最新 `version` 保留草稿重试。
- 照片逐张上传，每张成功后立即更新父点滴版本。中途失败时，已成功文件从待传队列移除，失败文件与后续文件保留；用户可以原地重试或取消，不必重新选图，也不会重复上传成功项。

## 可访问性与移动端

- 表单控件都有可关联标签；服务端字段错误显示在对应字段下并保留输入。
- 设置成员错误兼容服务端字段键 `members.0.displayName` / `members.1.displayName`。
- 保存、上传、断线、轮询、离线、失败和成功状态均有文字反馈。
- 主按钮和导航目标使用适合触摸的尺寸；删除确认包含对象名称；照片有替代文本。
- 手机顶栏可见实时连接状态与退出入口，退出失败会显示错误，不产生未处理 Promise。
- 390×844 冲突页面和主要移动流程已执行无横向溢出断言。
