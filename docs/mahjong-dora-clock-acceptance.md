## 行为与范围

旧版每张牌各自播放 2.4 秒的 CSS 动画，真实暗杠后手牌重排会重启已有宝牌的光泽，新宝牌也不同步。本步改为文档共享的一条帧循环，牌面、出牌动画、碰牌动画和拔北动画共同读取同一 UV 偏移。移除逐牌 CSSAnimation 时间复制，继续使用原创光带、授权牌面和实体几何。

共享循环只在连接正常的进行中牌局运行。减少动态效果、页面隐藏、断线和组件卸载时停止；恢复时保留原相位，不补算暂停时间。无需新增服务端任务、模型、指令、资料库迁移或计分变化。静态光泽不遮挡点按和拖牌。

参考为公开客户端 v0.11.252.w 的 RunUV 数值推进规律，默认速度覆盖值为零；固定源码摘要、隔离的数学类和五组轨迹均记录在测试夹具。仅执行隔离数学类以生成数值，不执行完整厂商程序，不提交其源码或美术素材。1512 个连续数值点包含 30/60/120Hz、混合帧和停顿帧。本步按同一输入 delta 验证偏移和速度，并使用 .8/.2 UV 缩放及纵向偏移；不宣称完整厂商着色器、像素、当前版本时钟域或全部体验一致。

## 失败与边界

早期仅检查状态推进而遗漏旧背景位置覆盖，出现“数值动、画面不动”；删除旧覆盖并增加实际位置差与数值映射断言后完整重跑。恢复检查曾在固定 60ms 处过早取值，改为限定 2 秒内等待实际循环恢复，不改变产品持续时间。组件测试发现 jsdom 无 matchMedia，使用能力检查处理，不跳过组件测试。

衔接测试最初混用 performance.now 墙钟和 RAF 帧时间，在负载下出现误差；现在两端均使用实际 RAF 时间，收紧到 1e-6ms，产品仍用同一 RAF 推进。保留旧 RED、早期不充分的 GREEN、恢复及墙钟探针失败日志；早期通过不作为最终画面证据。
